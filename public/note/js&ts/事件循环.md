# 事件循环

非常好的问题 👍
JavaScript 的 **事件循环（Event Loop）** 是理解异步执行机制（比如 `Promise`、`setTimeout`、`async/await`）的核心概念。
我们来分层次地讲清楚 👇

---

## 🧩 一、JavaScript 是单线程的

JavaScript 在浏览器或 Node.js 中都是**单线程**执行的，也就是说：

> 同一时间只能执行一个任务。

这条“主线程”负责执行所有代码。
如果某个任务太耗时（例如等待网络请求或定时器），就会阻塞后续代码。
所以引入了**异步机制**。

---

## 🕓 二、宏任务（Macro Task）与微任务（Micro Task）

事件循环的核心机制，就是通过**任务队列**来管理异步任务的执行。

任务分两类：

| 类型                     | 常见来源                                                                       | 举例                          |
| ------------------------ | ------------------------------------------------------------------------------ | ----------------------------- |
| **宏任务（Macro Task）** | 整体脚本、`setTimeout`、`setInterval`、I/O、事件回调                           | `setTimeout(() => {})`        |
| **微任务（Micro Task）** | `Promise.then`、`catch`、`finally`、`queueMicrotask`、`async/await` 的“后半段” | `Promise.resolve().then(...)` |

---

## 🔄 三、事件循环（Event Loop）执行顺序

**执行流程如下：**

1. 执行**一个宏任务**（例如整段脚本）。
2. 执行过程中遇到异步任务，放入对应队列：

   - `Promise.then()` → 放入 **微任务队列**
   - `setTimeout()` → 放入 **宏任务队列**

3. 当前宏任务执行完毕后，**立即清空所有微任务队列**。
4. 微任务执行完，再去取下一个宏任务。
5. 重复上述过程。

---

## 📜 四、举个例子

```js
console.log("1");

setTimeout(() => {
  console.log("2");
}, 0);

Promise.resolve().then(() => {
  console.log("3");
});

console.log("4");
```

执行顺序分析：

| 阶段                                                     | 输出 |
| -------------------------------------------------------- | ---- |
| 主线程（宏任务）执行：`console.log('1')`                 | → 1  |
| 主线程（宏任务）执行：`setTimeout(...)` 放入宏任务队列   |      |
| 主线程（宏任务）执行：`Promise.then(...)` 放入微任务队列 |      |
| 主线程（宏任务）执行：`console.log('4')`                 | → 4  |
| 清空微任务队列：`console.log('3')`                       | → 3  |
| 执行下一个宏任务（setTimeout）                           | → 2  |

最终输出顺序：

```
1
4
3
2
```

---

## ⚙️ 五、`async/await` 与事件循环的关系

`async/await` 本质上是对 `Promise` 的语法糖。

```js
async function test() {
  console.log("A");
  await Promise.resolve();
  console.log("B");
}
test();
console.log("C");
```

执行顺序：

```
A  // 立即执行
C  // 主线程继续
B  // await 后面的代码是微任务
```

---

## 🔍 六、简图示意

```
        ┌────────────────────────┐
        │      宏任务队列         │
        │ setTimeout / I/O / ... │
        └────────┬───────────────┘
                 │
        ┌────────▼──────────┐
        │     事件循环       │
        └────────▲──────────┘
                 │
        ┌────────┴───────────┐
        │     微任务队列      │
        │ Promise / await 等  │
        └────────────────────┘
```

---

## 🧠 小结

| 顺序 | 任务类型           | 示例                    | 优先级  |
| ---- | ------------------ | ----------------------- | ------- |
| 1    | 主线程执行（同步） | 普通代码                | ✅ 最高 |
| 2    | 微任务             | Promise、await 后的逻辑 | ✅ 次高 |
| 3    | 宏任务             | setTimeout、setInterval | ⏳ 最低 |

# Promise

非常好的问题 👍
`Promise` 是 JavaScript 中**异步编程的核心机制**之一，用来更优雅地处理异步操作（比如网络请求、文件读取、定时器等）。
我们从原理、状态变化、常用方法几个角度讲清楚 👇

---

## 🧩 一、Promise 是什么？

> `Promise` 是一个**代表未来某个异步操作结果**的对象。

你可以把它理解为一个“**未来值的占位符**”：

```js
const p = new Promise((resolve, reject) => {
  // 模拟异步
  setTimeout(() => {
    resolve("成功结果"); // 或 reject("错误信息")
  }, 1000);
});

p.then((result) => console.log(result));
```

上面的代码表示：

- 现在创建了一个 Promise；
- 1 秒后它会变成 “成功” 状态；
- `.then()` 注册了当它成功后要执行的逻辑。

---

## 🧠 二、Promise 的 3 种状态

| 状态          | 英文名 | 意义                           | 变化条件 |
| ------------- | ------ | ------------------------------ | -------- |
| **pending**   | 等待中 | 还未完成或失败                 | 初始状态 |
| **fulfilled** | 已成功 | 异步操作成功，调用 `resolve()` |          |
| **rejected**  | 已失败 | 异步操作失败，调用 `reject()`  |          |

👉 一旦从 `pending` 变为其他状态，就**不能再变化**（不可逆）。

---

## 🎯 三、Promise 的常用方法

### 1️⃣ `then(onFulfilled, onRejected)`

处理异步成功/失败的回调。

```js
fetchData()
  .then((data) => console.log("成功:", data))
  .catch((err) => console.error("失败:", err));
```

> `.then()` 返回一个新的 Promise，因此可以链式调用。

---

### 2️⃣ `catch(onRejected)`

只捕获失败的情况，相当于 `.then(undefined, onRejected)`：

```js
doSomething().catch((err) => console.error("错误:", err));
```

---

### 3️⃣ `finally(onFinally)`

无论成功还是失败，都会执行：

```js
doSomething()
  .then((res) => console.log("成功"))
  .catch((err) => console.log("失败"))
  .finally(() => console.log("任务结束"));
```

常用于清理、关闭 loading、释放资源。

---

### 4️⃣ `Promise.all(promises)`

并行执行多个 Promise，**全部成功**才返回结果。

```js
Promise.all([p1, p2, p3])
  .then(([r1, r2, r3]) => console.log("全部完成", r1, r2, r3))
  .catch((err) => console.error("有一个失败", err));
```

> 如果其中任何一个 reject，整个 `Promise.all` 会立即 reject。

---

### 5️⃣ `Promise.allSettled(promises)`

**等待所有 Promise 都结束（无论成功或失败）**，不会中断。

```js
Promise.allSettled([p1, p2]).then((results) => console.log(results));
```

结果格式：

```js
[
  { status: "fulfilled", value: "成功结果" },
  { status: "rejected", reason: "错误原因" },
];
```

---

### 6️⃣ `Promise.race(promises)`

返回**第一个完成（成功或失败）**的 Promise：

```js
Promise.race([slow(), fast()]).then((res) => console.log("最快的结果:", res));
```

常用于设置**超时机制**：

```js
Promise.race([
  fetch("/api/data"),
  new Promise((_, reject) => setTimeout(() => reject("超时"), 5000)),
]);
```

---

### 7️⃣ `Promise.any(promises)`

返回**第一个成功**的 Promise；如果都失败则返回 `AggregateError`：

```js
Promise.any([p1, p2, p3])
  .then((res) => console.log("第一个成功:", res))
  .catch((err) => console.error("全部失败", err));
```

---

### 8️⃣ `Promise.resolve(value)`

快速创建一个立即成功的 Promise：

```js
Promise.resolve(42).then((v) => console.log(v)); // 42
```

---

### 9️⃣ `Promise.reject(reason)`

快速创建一个立即失败的 Promise：

```js
Promise.reject("出错了").catch((err) => console.error(err));
```

---

## 🧭 四、Promise 链式调用原理

```js
fetchUser()
  .then((user) => fetchProfile(user.id))
  .then((profile) => fetchPosts(profile.id))
  .then((posts) => console.log(posts))
  .catch((err) => console.error(err));
```

> 每个 `.then()` 返回一个新的 Promise，
> 上一个返回值会自动传入下一个回调。

---

## ⚙️ 五、与 `async/await` 的关系

`async/await` 是对 Promise 的语法糖，等价于链式 `.then()`：

```js
async function run() {
  try {
    const user = await fetchUser();
    const profile = await fetchProfile(user.id);
    console.log(profile);
  } catch (err) {
    console.error(err);
  }
}
```

> 底层依然是 Promise，只是写法更像同步代码。

---

## 🧠 六、常见错误点

| 错误写法                          | 问题原因           |
| --------------------------------- | ------------------ |
| 忘记返回 Promise                  | 会导致链断裂       |
| `.then()` 里抛异常但没 `.catch()` | 无法捕获错误       |
| 在循环中直接 `await`              | 串行执行，性能低   |
| 滥用 `Promise.all`                | 任意任务出错会中断 |

---

## ✅ 七、总结

| 方法           | 作用                     |
| -------------- | ------------------------ |
| `then()`       | 处理成功或失败           |
| `catch()`      | 捕获错误                 |
| `finally()`    | 无论成功失败都执行       |
| `all()`        | 并行执行，全部成功才返回 |
| `allSettled()` | 等所有都结束             |
| `race()`       | 谁先结束返回谁           |
| `any()`        | 谁先成功返回谁           |
| `resolve()`    | 快速创建成功 Promise     |
| `reject()`     | 快速创建失败 Promise     |

# async

非常好，这个问题问得非常深入 👍
理解 **`async` 的执行逻辑** 是掌握现代 JavaScript 异步编程的关键。
我们来一步步分析 `async` 的运行机制、内部原理、执行顺序和常见陷阱 👇

---

## 🧩 一、`async` 是什么？

> `async` 是对 `Promise` 的语法糖。
> 它让你用**同步的写法**实现**异步的逻辑**。

示例：

```js
async function getData() {
  const res = await fetch("/api/data");
  console.log("数据:", res);
}
```

其实底层等价于：

```js
function getData() {
  return fetch("/api/data").then((res) => {
    console.log("数据:", res);
  });
}
```

---

## ⚙️ 二、执行机制拆解

当你定义一个 `async` 函数时：

```js
async function foo() {
  return 42;
}
```

### 👉 1. `async` 函数一定返回一个 Promise

即使你返回的是普通值：

```js
foo(); // 返回 Promise<42>
```

相当于：

```js
function foo() {
  return Promise.resolve(42);
}
```

---

## 🧭 三、`await` 的作用与执行逻辑

`await` 的作用是：

> “暂停”当前 `async` 函数的执行，等待右侧表达式的 Promise 结果。

例如：

```js
async function demo() {
  console.log(1);
  const res = await fetchData();
  console.log(2);
}
```

执行顺序：

```
1 → fetchData() 开始执行 → demo 暂停（让出事件循环）
→ fetchData() 结束后恢复执行 → 输出 2
```

---

## 🔁 四、事件循环中的执行顺序

我们来看一个经典例子：

```js
async function test() {
  console.log("A");
  await Promise.resolve();
  console.log("B");
}
test();
console.log("C");
```

输出顺序是：

```
A
C
B
```

解释：

1. 执行到 `await Promise.resolve()` 时，`await` 会：

   - 暂停当前函数；
   - 把后续代码（`console.log('B')`）放到 **微任务队列（microtask queue）**；

2. 主线程继续执行同步任务；
3. 同步任务执行完（输出 `C`）后；
4. 事件循环从微任务队列取出任务，执行 `console.log('B')`。

> ✅ 所以 `await` 不是完全阻塞，而是**让出执行权**，等待 Promise 结果后再回来。

---

## 🔍 五、`await` 后的表达式规则

| 表达式               | 行为                          |
| -------------------- | ----------------------------- |
| 普通值               | 立即返回该值                  |
| Promise              | 等待 Promise 结果             |
| 被 reject 的 Promise | 抛出异常，需要 try/catch 捕获 |

示例：

```js
async function run() {
  console.log(await 42); // 输出 42
  console.log(await Promise.resolve("ok")); // 输出 ok
  await Promise.reject("出错了"); // 抛出异常
}
```

等价于：

```js
Promise.resolve(42)
  .then(() => Promise.resolve("ok"))
  .then(() => Promise.reject("出错了"))
  .catch((err) => console.error(err));
```

---

## 🧱 六、错误处理

`await` 语句后如果 Promise 被拒绝（reject），
会抛出异常，需要使用 `try...catch`：

```js
async function run() {
  try {
    const res = await fetch("/api/fail");
  } catch (err) {
    console.error("捕获错误:", err);
  }
}
```

> 等价于 `promise.catch()`，但写法更清晰。

---

## ⚙️ 七、多个 `await` 的执行方式

```js
async function run() {
  const a = await taskA();
  const b = await taskB();
}
```

上面是**串行执行**：`taskB` 要等 `taskA` 完成后才开始。
如果希望并发执行，应写成：

```js
async function run() {
  const [a, b] = await Promise.all([taskA(), taskB()]);
}
```

> ⚠️ 许多人以为多个 await 会并行执行，但其实是**顺序执行**。

---

## 🧩 八、执行过程完整图解（逻辑层面）

假设：

```js
async function foo() {
  console.log(1);
  await bar();
  console.log(2);
}
```

执行步骤：

1. 调用 `foo()`；
2. 输出 `1`；
3. 执行 `bar()`，并等待结果；
4. `foo()` 暂停执行，返回一个 pending Promise；
5. 当前事件循环结束；
6. `bar()` resolve → 微任务队列中加入恢复 `foo` 的任务；
7. 执行微任务，打印 `2`；
8. `foo()` 的 Promise 状态变为 fulfilled。

---

## 🧠 九、总结对比表

| 特性     | Promise            | async/await          |
| -------- | ------------------ | -------------------- |
| 写法风格 | 链式 `.then()`     | 类同步结构           |
| 异常捕获 | `.catch()`         | `try...catch`        |
| 返回值   | 直接返回 Promise   | 自动包装为 Promise   |
| 可读性   | 嵌套深时较差       | 清晰、接近同步逻辑   |
| 控制并发 | 使用 `Promise.all` | 同样依赖 Promise.all |

---

## ✅ 十、一句话总结

> `async` 函数始终返回一个 Promise；
> `await` 会暂停函数执行，等待 Promise 结果后再继续；
> 执行过程基于事件循环中的“**微任务队列**”，不会阻塞主线程。
