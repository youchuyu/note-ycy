# 强缓存/协商缓存

在前端优化和浏览器缓存机制中，**强缓存** 和 **协商缓存** 是两个非常核心的概念，它们可以显著提升页面加载速度、减轻服务器压力。

---

## 🧊 一、强缓存（**强制缓存 / 强制使用本地缓存**）

### ✅ 定义：

强缓存表示：**在规定的时间内，浏览器直接使用本地缓存文件，不会向服务器发起请求**。

---

### 📦 实现方式：

通过响应头的以下字段实现：

| 响应头字段      | 示例                                     | 说明                                |
| --------------- | ---------------------------------------- | ----------------------------------- |
| `Expires`       | `Expires: Wed, 22 May 2025 10:00:00 GMT` | HTTP/1.0 设定的过期时间（绝对时间） |
| `Cache-Control` | `Cache-Control: max-age=3600`            | HTTP/1.1 推荐使用（相对时间）       |

如果还在有效期内，浏览器直接使用缓存文件（200 from disk/memory cache）。

---

### 📌 特点：

- 不发起请求，速度最快
- 依赖时间控制
- 一旦缓存过期，才进行下一步的协商缓存检查

---

## 🔁 二、协商缓存（**对比缓存 / 条件缓存**）

### ✅ 定义：

协商缓存表示：**浏览器向服务器发起请求，同时带上缓存标识，服务器对比后决定是否使用缓存内容**。

---

### 📦 实现方式：

通过两个响应头 + 两个请求头完成协商过程：

| 响应头（第一次返回时） | 对应的请求头（下一次请求时携带） | 作用                           |
| ---------------------- | -------------------------------- | ------------------------------ |
| `Last-Modified`        | `If-Modified-Since`              | 比较资源最后修改时间           |
| `ETag`（实体标签）     | `If-None-Match`                  | 比较资源内容是否变更（更精准） |

---

### 📌 过程示例：

1. 第一次请求返回：

```http
200 OK
Cache-Control: no-cache
Last-Modified: Tue, 25 May 2025 10:00:00 GMT
ETag: "abc123"
```

2. 下一次请求时浏览器发送：

```http
GET /style.css
If-Modified-Since: Tue, 25 May 2025 10:00:00 GMT
If-None-Match: "abc123"
```

3. 如果资源没变化，服务器返回：

```http
304 Not Modified
```

浏览器继续使用本地缓存，但确认过是最新的。

---

### 📌 特点：

- 会发起请求，但不会下载内容（若没变化）
- 相比强缓存，响应速度略慢
- 更适合频繁更新的资源

---

## 🔍 强缓存 vs 协商缓存 对比表：

| 特性             | 强缓存                     | 协商缓存                |
| ---------------- | -------------------------- | ----------------------- |
| 是否发请求       | ❌ 不发请求                | ✅ 发请求               |
| 响应状态码       | `200 (from cache)`         | `304 Not Modified`      |
| 是否使用本地缓存 | ✅ 是                      | ✅ 是（条件成立时）     |
| 控制字段         | `Cache-Control`, `Expires` | `Last-Modified`, `ETag` |
| 优先级           | ✅ 优先于协商缓存          | -                       |

---

## 💡 浏览器缓存流程图：

```text
资源请求 →
    是否命中强缓存（未过期）？
        → 是：使用本地缓存，返回 200 (from cache)
        → 否：
            发起请求，带上协商缓存字段（如 ETag）
            服务器是否资源有变化？
                → 没变：返回 304 Not Modified
                → 有变：返回新资源，状态码 200 OK
```

---

## 🛠 最佳实践建议

| 场景                    | 推荐策略                             |
| ----------------------- | ------------------------------------ |
| 静态资源（JS/CSS/图片） | 使用强缓存，搭配版本号（`v=123`）    |
| 动态接口数据            | 使用协商缓存（ETag / Last-Modified） |
| 高频更新资源            | 使用短强缓存 + 协商缓存结合          |

# 路由编码

**URL 编码**（URL encoding，也叫 percent-encoding），是为了确保 URL 在互联网上传输时的安全性和兼容性。

---

### ✅ 原因：URL 对字符的要求

URL（统一资源定位符）中**只能包含 ASCII 字符**，不允许出现空格、中文、特殊符号（如 `#`, `?`, `&` 等）。为了保证这些字符能被安全传输和正确解析，浏览器或框架会自动将它们编码成符合标准的形式。

---

### ✅ 什么会被编码？

- 中文、日文等非 ASCII 字符
- 空格（编码为 `%20`）
- 特殊符号，如：

  - `/`、`?`、`#`、`&`、`=`、`+` 等有特定含义的字符
  - `"`、`<`、`>`、`%` 等可能引起解析歧义的字符

---

### ✅ 例子：

原始路径：

```text
/note/ai/数据结构
```

编码后变成：

```text
/note/ai/%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84
```

这是 `"数据结构"` 的 UTF-8 编码再以百分号表示。

---

### ✅ 实际用途示例：

假如你传一个 URL 到服务器中：

```js
fetch(`/search?q=数据`);
```

浏览器实际上发送的是：

```text
/search?q=%E6%95%B0%E6%8D%AE
```

这确保服务器能正确解析成原始字符串 `"数据"`，而不会误将 `?q=数据` 中的 `?` 或其他字符当作路径分隔符等。

---

### ✅ 总结：

| 项目               | 是否允许在 URL 中直接使用 | 是否需要编码 |
| ------------------ | ------------------------- | ------------ |
| 英文和数字         | ✅ 是                     | ❌ 否        |
| 中文               | ❌ 否                     | ✅ 是        |
| 特殊符号（如 `&`） | ❌ 否                     | ✅ 是        |

---

# DOMContentLoaded 事件和 load 事件有什么区别

好的，我们来系统梳理一下 **`DOMContentLoaded`** 和 **`load`** 事件的区别，这是前端页面加载性能和事件管理中非常重要的概念。

---

## 🧩 一、定义对比

| 事件               | 触发时机                                         | 包含资源                                          | 用途                                       |
| ------------------ | ------------------------------------------------ | ------------------------------------------------- | ------------------------------------------ |
| `DOMContentLoaded` | 当 **HTML 文档被完全解析**，DOM 树构建完成时触发 | 不等待图片、CSS、iframe、音视频等外部资源加载完成 | 可以安全操作 DOM，绑定事件、初始化组件     |
| `load`             | 当 **页面及其所有资源完全加载** 后触发           | 图片、CSS、JS、iframe、字体等所有资源都加载完成   | 确保页面完全渲染，可执行依赖外部资源的逻辑 |

---

## 🏗️ 二、触发顺序

1. 浏览器开始解析 HTML
2. 遇到 `<script>` 标签：

   - 默认阻塞 DOM 解析，执行 JS

3. DOM 树解析完成 → **`DOMContentLoaded`**
4. 页面所有外部资源加载完成 → **`load`**

> 🔹 简单记忆：
>
> - `DOMContentLoaded` = DOM 可操作
> - `load` = 页面完全可用（含图片、iframe、字体等）

---

## 🏷️ 三、代码示例

```js
// DOM 解析完成触发
document.addEventListener("DOMContentLoaded", () => {
  console.log("DOM 已经解析完成，可以安全操作 DOM");
});

// 页面及资源加载完成触发
window.addEventListener("load", () => {
  console.log("页面及所有资源加载完成");
});
```

---

### 示例对比：

```html
<img src="large-image.jpg" />
<script>
  document.addEventListener("DOMContentLoaded", () =>
    console.log("DOMContentLoaded")
  );
  window.addEventListener("load", () => console.log("load"));
</script>
```

- 如果 `large-image.jpg` 加载很慢：

  - `DOMContentLoaded` 可能很快触发
  - `load` 要等图片加载完成才触发

---

## ⚡ 四、使用场景

| 事件               | 适用场景                                     |
| ------------------ | -------------------------------------------- |
| `DOMContentLoaded` | 初始化 DOM、绑定事件、渲染组件、计算元素尺寸 |
| `load`             | 页面依赖资源完全加载的场景，如：             |

- 大图懒加载
- Canvas/图片绘制
- 第三方 SDK 初始化 |

---

## 🧠 五、优化建议

1. **尽量用 `DOMContentLoaded`** 初始化页面逻辑，避免阻塞
2. **`load` 仅用于依赖外部资源的逻辑**
3. SPA 通常在路由挂载或组件挂载时初始化，不依赖 `load`
4. 可结合 **Performance API** 分析加载性能：

```js
window.addEventListener("load", () => {
  console.log("页面完全加载耗时:", performance.now());
});
```

---

✅ 总结：

- **`DOMContentLoaded`** = DOM 树完成，适合操作 DOM
- **`load`** = 页面及所有资源加载完成，适合依赖资源的操作
- **触发顺序**：`DOMContentLoaded` → `load`

# navigator

好的，我们来系统介绍一下 **`navigator`** 对象，这是前端 JavaScript 中用于获取 **浏览器信息、设备信息和网络状态** 的核心对象。

---

## 🧩 一、什么是 `navigator`

- `navigator` 是浏览器提供的 **全局对象**，属于 **`window.navigator`**
- 主要用途：

  1. 获取浏览器信息（User Agent、版本、平台）
  2. 获取设备信息（在线状态、语言）
  3. 检测网络状况
  4. 提供一些浏览器能力 API

> `navigator` 对象大部分属性只读，不能修改浏览器本身信息。

---

## 🏗️ 二、常用属性

| 属性                            | 描述                                    | 示例                                             |
| ------------------------------- | --------------------------------------- | ------------------------------------------------ |
| `navigator.userAgent`           | 浏览器 User Agent 字符串                | `'Mozilla/5.0 (Windows NT 10.0; Win64; x64)...'` |
| `navigator.platform`            | 操作系统平台                            | `'Win32'`、`'MacIntel'`                          |
| `navigator.appVersion`          | 浏览器版本信息                          | `'5.0 (Windows)...'`                             |
| `navigator.language`            | 浏览器首选语言                          | `'zh-CN'`                                        |
| `navigator.languages`           | 支持的语言列表                          | `['zh-CN','en-US']`                              |
| `navigator.onLine`              | 网络是否在线                            | `true` / `false`                                 |
| `navigator.cookieEnabled`       | 是否启用 Cookie                         | `true` / `false`                                 |
| `navigator.hardwareConcurrency` | CPU 核心数                              | `4`                                              |
| `navigator.deviceMemory`        | 设备内存 (GB)                           | `8`                                              |
| `navigator.connection`          | 网络信息对象（Network Information API） | `{effectiveType: '4g', downlink: 10, rtt: 50}`   |
| `navigator.geolocation`         | 地理定位 API                            | `navigator.geolocation.getCurrentPosition(...)`  |
| `navigator.clipboard`           | 剪贴板 API                              | `navigator.clipboard.writeText('Hello')`         |

---

## 🏗️ 三、常用方法

| 方法                                                       | 描述                     | 示例                                                                        |
| ---------------------------------------------------------- | ------------------------ | --------------------------------------------------------------------------- |
| `navigator.geolocation.getCurrentPosition(success, error)` | 获取用户位置             | `navigator.geolocation.getCurrentPosition(pos => console.log(pos.coords));` |
| `navigator.geolocation.watchPosition(success, error)`      | 监听位置变化             | 监听 GPS 移动                                                               |
| `navigator.clipboard.writeText(text)`                      | 写入剪贴板               | `navigator.clipboard.writeText('Hello')`                                    |
| `navigator.clipboard.readText()`                           | 读取剪贴板               | `const text = await navigator.clipboard.readText();`                        |
| `navigator.registerProtocolHandler()`                      | 注册自定义协议处理       | 注册 mailto、web+ 自定义协议                                                |
| `navigator.sendBeacon(url, data)`                          | 异步发送数据，常用于统计 | `navigator.sendBeacon('/log', JSON.stringify(data));`                       |

---

## 🏷️ 四、Network Information API

- `navigator.connection` 提供网络状况信息

```js
const connection = navigator.connection;
console.log(connection.effectiveType); // '2g', '3g', '4g', 'slow-2g'
console.log(connection.downlink); // Mbps
console.log(connection.rtt); // 延迟 ms
console.log(connection.saveData); // 节省流量模式
```

- 可监听网络状态变化：

```js
connection.addEventListener("change", () => {
  console.log("网络状态变化:", connection.effectiveType);
});
```

---

## 🏷️ 五、使用场景

1. **用户体验优化**

   - 根据 `navigator.language` 显示多语言
   - 根据 `navigator.onLine` 弱网提示
   - 根据 `navigator.connection.effectiveType` 动态降低图片质量

2. **设备适配**

   - 根据 `navigator.platform` / `hardwareConcurrency` 调整性能
   - Canvas、WebGL 等渲染优化

3. **权限和能力检测**

   - `navigator.geolocation` 判断是否支持定位
   - `navigator.clipboard` 判断剪贴板能力

---

## ⚡ 六、注意事项

1. **安全与隐私**

   - 某些属性可能受浏览器隐私设置影响（如 geolocation 需用户授权）

2. **兼容性**

   - `navigator.connection`、`clipboard` 等 API 不是所有浏览器都支持，需要判断：

```js
if (navigator.connection) { ... }
if (navigator.clipboard) { ... }
```

3. **只读**

   - 无法修改 `userAgent` 或 `platform` 等信息

---

## 🧠 七、总结

- `navigator` = 浏览器 & 设备信息集合 + 一些浏览器能力 API
- 常用功能：

  1. **浏览器 / 语言 /平台信息** → UA 判断、国际化
  2. **网络信息** → 弱网检测、优化资源加载
  3. **设备信息** → 性能优化
  4. **能力检测** → 剪贴板、定位、发送统计

> 🔑 核心思想：通过 `navigator` 获取环境信息，根据环境动态调整前端行为，提高性能和用户体验。

# cookie 可以实现不同域共享吗

好的，这是一个非常重要且常见的问题。我来详细解释 Cookie 在不同域之间的共享能力。

## 一、简短回答

**默认情况下，Cookie 不能在不同域之间直接共享。** 但是，通过特定的技术手段，**可以实现有限的、受控的跨域 Cookie 共享**。

## 二、Cookie 的作用域规则

### 1. 默认行为：同源策略

```http
# 在 domain-a.com 设置的 Cookie
Set-Cookie: user_id=123; Domain=domain-a.com; Path=/

# 这个 Cookie 只能被：
# ✅ domain-a.com 及其子域名访问
# ❌ domain-b.com 无法访问
# ❌ other-domain.com 无法访问
```

### 2. Cookie 的作用域属性

```javascript
// 设置 Cookie 时的作用域控制
document.cookie = "name=value; domain=example.com; path=/";

// 或服务器端设置
// Set-Cookie: name=value; domain=example.com; path=/
```

## 三、实现跨域 Cookie 共享的技术方案

### 1. 设置 Domain 为公共父域名

```javascript
// 如果两个域名有共同的父域名
// ✅ app1.example.com 和 app2.example.com 可以共享

// 在任意子域名设置，指定父域名
document.cookie = "shared_token=abc123; domain=.example.com; path=/";

// 现在以下域名都能访问这个 Cookie：
// ✅ app1.example.com
// ✅ app2.example.com
// ✅ api.example.com
// ✅ example.com
```

### 2. CORS 跨域请求携带 Cookie

```javascript
// 前端：需要设置 withCredentials
fetch("https://api.other-domain.com/data", {
  method: "GET",
  credentials: "include", // 关键：携带 Cookie
});

// XMLHttpRequest
const xhr = new XMLHttpRequest();
xhr.withCredentials = true;
xhr.open("GET", "https://api.other-domain.com/data");
```

```javascript
// 后端：需要设置 CORS 头部
app.get("/data", (req, res) => {
  // 允许特定源访问
  res.header("Access-Control-Allow-Origin", "https://your-domain.com");
  // 允许携带 Cookie
  res.header("Access-Control-Allow-Credentials", "true");
  // 允许的头部
  res.header("Access-Control-Allow-Headers", "Content-Type");

  // 现在可以读取跨域请求中的 Cookie
  const userCookie = req.cookies.user_id;
  res.json({ data: "some data", user: userCookie });
});
```

### 3. 使用中间页面中转

```html
<!-- 在 domain-a.com -->
<script>
  // 检查是否已有共享的 Cookie
  if (!getCookie("shared_data")) {
    // 跳转到认证页面
    window.location.href =
      "https://auth-domain.com/share?return=" +
      encodeURIComponent(window.location.href);
  }
</script>
```

```javascript
// 在 auth-domain.com 的认证页面
// 设置共享 Cookie
document.cookie = "shared_data=user_info; domain=.auth-domain.com; path=/";

// 然后跳转回原域名
const returnUrl = new URLSearchParams(window.location.search).get("return");
window.location.href = returnUrl;
```

## 四、单点登录 (SSO) 方案

这是企业级应用中最常见的跨域认证方案。

### 1. 中央认证服务

```javascript
// 在中央认证域名 sso-auth.com
class SSOAuth {
  // 用户登录
  login(username, password) {
    // 验证用户身份
    const token = generateAuthToken(username);

    // 设置中央认证 Cookie
    document.cookie = `sso_token=${token}; domain=.sso-auth.com; path=/; max-age=3600`;

    // 返回给调用方
    return token;
  }

  // 验证 token
  validateToken(token) {
    // 验证逻辑
    return { isValid: true, user: { id: 1, name: "john" } };
  }
}
```

### 2. 应用 A (app-a.com) 的集成

```javascript
// app-a.com
class AppA {
  constructor() {
    this.checkAuth();
  }

  checkAuth() {
    // 检查本地是否有 token
    const localToken = this.getLocalToken();

    if (!localToken) {
      // 跳转到 SSO 认证
      this.redirectToSSO();
    } else {
      // 验证 token
      this.validateWithSSO(localToken);
    }
  }

  redirectToSSO() {
    const returnUrl = encodeURIComponent(window.location.href);
    window.location.href = `https://sso-auth.com/login?return=${returnUrl}&app=app-a`;
  }

  validateWithSSO(token) {
    // 向 SSO 服务验证 token
    fetch("https://sso-auth.com/validate", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ token, app: "app-a" }),
      credentials: "include",
    })
      .then((response) => response.json())
      .then((data) => {
        if (data.isValid) {
          this.onAuthSuccess(data.user);
        } else {
          this.redirectToSSO();
        }
      });
  }
}
```

### 3. 应用 B (app-b.com) 的集成

```javascript
// app-b.com - 类似的逻辑
class AppB {
  checkAuth() {
    const localToken = this.getLocalToken();

    if (!localToken) {
      // 检查 SSO 服务是否有认证
      this.checkSSOStatus();
    }
  }

  checkSSOStatus() {
    // 使用隐藏的 iframe 检查 SSO 状态
    const iframe = document.createElement("iframe");
    iframe.src = "https://sso-auth.com/check-auth";
    iframe.style.display = "none";

    iframe.onload = () => {
      // iframe 可以读取 sso-auth.com 的 Cookie
      // 通过 postMessage 通信获取认证状态
    };

    document.body.appendChild(iframe);
  }
}
```

## 五、现代替代方案

### 1. OAuth 2.0 / OpenID Connect

```javascript
// 使用标准的 OAuth2 流程
class OAuth2Client {
  async startAuthFlow() {
    // 重定向到认证服务器
    const authUrl = new URL("https://auth-server.com/oauth/authorize");
    authUrl.searchParams.set("client_id", "your-client-id");
    authUrl.searchParams.set("redirect_uri", "https://your-app.com/callback");
    authUrl.searchParams.set("response_type", "code");
    authUrl.searchParams.set("scope", "openid profile");
    authUrl.searchParams.set("state", this.generateState());

    window.location.href = authUrl.toString();
  }

  async handleCallback(code) {
    // 用授权码换取 access token
    const response = await fetch("https://auth-server.com/oauth/token", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        client_id: "your-client-id",
        client_secret: "your-client-secret",
        code: code,
        grant_type: "authorization_code",
        redirect_uri: "https://your-app.com/callback",
      }),
    });

    const tokens = await response.json();
    this.storeTokens(tokens);
  }
}
```

### 2. JWT (JSON Web Tokens)

```javascript
// 使用 JWT 代替 Cookie 进行跨域认证
class JWTClient {
  // 登录后获取 JWT
  async login(credentials) {
    const response = await fetch("https://api.example.com/auth/login", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(credentials),
    });

    const { accessToken, refreshToken } = await response.json();

    // 存储到 localStorage
    localStorage.setItem("access_token", accessToken);
    localStorage.setItem("refresh_token", refreshToken);
  }

  // 在 API 请求中使用 JWT
  async fetchProtectedData() {
    const token = localStorage.getItem("access_token");

    const response = await fetch("https://api.example.com/protected-data", {
      headers: {
        Authorization: `Bearer ${token}`,
        "Content-Type": "application/json",
      },
    });

    return response.json();
  }
}
```

app.use((req, res, next) => {
  const allowedOrigins = [
    "https://app1.example.com",
    "https://app2.example.com",
  ];

  const origin = req.headers.origin;
  if (allowedOrigins.includes(origin)) {
    res.header("Access-Control-Allow-Origin", origin);

## 七、实际示例：跨域购物车

```javascript
// 电商平台：主站 + 多个子商城的购物车共享
class CrossDomainCart {
  constructor() {
    this.ssoDomain = "sso.mall.com";
    this.cartApi = "https://api.mall.com/cart";
  }

  // 添加到购物车
  async addToCart(productId, quantity) {
    // 获取用户 token
    const token = await this.getUserToken();

    // 调用购物车 API
    const response = await fetch(this.cartApi, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${token}`,
      },
      body: JSON.stringify({
        productId,
        quantity,
        source: window.location.hostname,
      }),
    });

    return response.json();
  }

  // 获取用户 token
  async getUserToken() {
    let token = localStorage.getItem("user_token");

    if (!token) {
      // 跳转到 SSO 认证
      const returnUrl = encodeURIComponent(window.location.href);
      window.location.href = `https://${this.ssoDomain}/auth?return=${returnUrl}`;
    }

    return token;
  }
}
```

| 方案          | 实现难度 | 安全性 | 适用场景           |
| ------------- | -------- | ------ | ------------------ |
| 公共父域名    | 简单     | 中等   | 同公司的多个子域名 |
| CORS + Cookie | 中等     | 高     | API 跨域调用       |
| SSO 单点登录  | 复杂     | 高     | 企业级多应用系统   |
| OAuth 2.0     | 复杂     | 很高   | 第三方应用集成     |
| JWT           | 中等     | 高     | 现代前后端分离应用 |

**推荐做法**：

- 对于内部系统：使用公共父域名方案
- 对于现代 Web 应用：优先考虑 JWT + API 认证
- 对于企业级应用：使用标准的 OAuth 2.0 / SSO 方案
- 始终考虑安全因素：使用 HTTPS、HttpOnly、SameSite 等安全属性

# dispatchEvent

`window.dispatchEvent()` 是浏览器中用于**主动触发事件**（包括自定义事件）的一个标准方法。
它配合 `window.addEventListener()` 一起使用，是浏览器事件机制中非常重要的一环。

---

## 🧠 一、基本作用

`dispatchEvent` 用于在一个对象（比如 `window`、`document`、DOM 元素）上**派发事件（dispatch event）**，从而触发之前注册的事件监听器。

换句话说，它的作用相当于：

> “**手动触发一个事件**，让监听这个事件的函数执行。”

---

## 📜 二、基本语法

```js
target.dispatchEvent(event);
```

- **target**：要触发事件的目标对象（比如 `window`、`document`、某个 DOM 元素）。
- **event**：要触发的事件对象（通过 `new Event()` 或 `new CustomEvent()` 创建）。

返回值是一个布尔值，表示事件是否被 `preventDefault()` 阻止了。

---

## 💡 三、基础示例

### 1️⃣ 触发内置事件

```js
window.addEventListener("resize", () => {
  console.log("触发了 resize 事件");
});

// 主动触发
window.dispatchEvent(new Event("resize"));
```

输出：

```
触发了 resize 事件
```

---

### 2️⃣ 触发自定义事件（CustomEvent）

如果你想传递数据，就要用 `CustomEvent`：

```js
// 监听事件
window.addEventListener("userChange", (e) => {
  console.log("新用户信息:", e.detail);
});

// 创建并触发事件
const event = new CustomEvent("userChange", {
  detail: { name: "Tom", age: 18 },
});
window.dispatchEvent(event);
```

输出：

```
新用户信息: { name: 'Tom', age: 18 }
```

---

## ⚙️ 四、事件机制说明

当你调用 `dispatchEvent(event)` 时，浏览器会：

1. 根据事件类型，找到目标对象上注册的事件监听器；
2. 执行监听器函数；
3. 如果事件支持冒泡（`bubbles: true`），会从目标元素向上冒泡到父级；
4. 如果有调用 `event.preventDefault()` 并且事件可取消（`cancelable: true`），则返回 `false`。

---

## 🧩 五、自定义事件的高级用法

可以控制事件的冒泡和可取消性：

```js
const event = new CustomEvent("themeChange", {
  detail: { theme: "dark" },
  bubbles: true, // 允许事件冒泡
  cancelable: true, // 允许被 preventDefault()
});

document.body.addEventListener("themeChange", (e) => {
  console.log("Body 收到主题变更:", e.detail);
});

// 触发事件（从 window 开始）
window.dispatchEvent(event);
```

---

## 🚀 六、常见应用场景

| 场景                 | 示例                                                             |
| -------------------- | ---------------------------------------------------------------- |
| **全局状态更新通知** | 主应用通过 `window.dispatchEvent` 通知子应用主题变化、登录态变更 |
| **跨模块通信**       | 不同组件之间不方便建立直接引用时使用                             |
| **微前端通信**       | 主、子应用间通过自定义事件广播消息（不依赖框架）                 |
| **测试模拟事件**     | 单元测试中模拟用户交互或浏览器事件                               |

---

| 方法                                 | 是否支持跨域 | 是否可携带数据 | 是否依赖框架       |
| ------------------------------------ | ------------ | -------------- | ------------------ |
