## 版本语义化

在 npm 或 Yarn 的版本控制中，除了 ^（脱字符号）之外，还有其他符号可以用来定义版本范围。不同的符号用于表达你希望如何管理依赖的版本。

1. ^（Caret 符号）
   • 用途：默认情况下，^ 允许安装主版本号（major）不变的更新。对于 0.x.x 的版本，^ 会限制更新在补丁（patch）和小版本（minor）范围内。
   • ^1.2.3 会匹配 1.2.3 到 1.x.x（如 1.5.0），但不会匹配 2.0.0。
   • ^0.5.15 会匹配 0.5.x 的版本，如 0.5.16 或 0.9.9，但不会跳到 0.6.0 或 1.0.0。

2. ~（Tilde 符号）
   • 用途：~ 允许安装当前版本的补丁（patch）版本更新，但不会跨越小版本（minor）或主版本（major）。
   • ~1.2.3 会匹配 1.2.3 到 1.2.x（例如 1.2.5），但不会匹配 1.3.0 或更高版本。
   • ~0.5.15 会匹配 0.5.15 到 0.5.x（例如 0.5.18），但不会匹配 0.6.0 或更高版本。

3. \> （大于符号）
   • 用途：指定版本必须大于给定版本。
   • >1.2.3：会匹配任何比 1.2.3 版本更新的版本，如 1.2.4, 1.3.0, 2.0.0 等。

4. \>=（大于等于符号）
   • 用途：指定版本必须大于或等于给定版本。
   • >=1.2.3：会匹配 1.2.3 或更高版本的所有版本，如 1.2.4, 2.0.0 等。

5. <（小于符号）
   • 用途：指定版本必须小于给定版本。
   • <1.2.3：会匹配所有比 1.2.3 版本旧的版本，如 1.2.2, 1.1.0 等。

6. <=（小于等于符号）
   • 用途：指定版本必须小于或等于给定版本。
   • <=1.2.3：会匹配 1.2.3 或更低版本的所有版本，如 1.2.2, 1.0.0 等。

7. _（星号）
   • 用途：表示匹配任意版本，通常用来表示没有版本限制。
   • _：可以匹配任何版本的依赖。
   • 1._._：表示匹配 1.x.x 的任何版本，即 1.0.0 到 1.9.9 等。

8. x（X 或 NPM 默认版本范围）
   • 用途：x 表示任意版本，类似于 \*。它通常用于表示版本不严格指定的情况。
   • 1.2.x：表示匹配 1.2.x 版本中的任意版本，如 1.2.0, 1.2.1, 1.2.9 等。

9. ||（或符号）
   • 用途：允许指定多个版本范围，其中一个条件满足即可。
   • >=1.2.0 || ^2.0.0：表示匹配版本 1.2.0 或更高版本，或者是 2.x.x 版本。

10. -（范围符号）
    • 用途：可以指定一个版本范围，通常用于定义一个版本区间。
    • 1.2.3 - 1.5.0：表示匹配版本在 1.2.3 和 1.5.0 之间的所有版本（包括 1.2.3 和 1.5.0）。

11. ^ 和 ~ 的差异总结：
    • ^：允许更新 小版本号 和 补丁版本，但不会升级到 主版本。
    • 例：^1.2.3 允许匹配 1.3.0 但不匹配 2.0.0。
    • ~：只允许更新 补丁版本，不会更新小版本号。
    • 例：~1.2.3 允许匹配 1.2.4，但不匹配 1.3.0。

总结：

符号 含义 示例
^ 主版本不变，允许小版本和补丁版本更新 ^1.2.3 匹配 1.2.4，不匹配 2.0.0
~ 只允许补丁版本更新 ~1.2.3 匹配 1.2.4，不匹配 1.3.0

这些符号帮助你更灵活地控制项目依赖的版本范围，确保项目的兼容性和更新。

## peerDependencies

在 Node.js 和 JavaScript 项目中，peerDependencies 是一个非常重要的概念，它用于描述一个包与另一个包之间的关系，通常用于插件或库的开发，确保插件和主库的版本兼容性。

### peerDependencies 的定义

peerDependencies 是一个在 package.json 中指定的字段，用来声明你的包依赖于另一个包，但你希望依赖的包版本由使用你这个包的项目来管理，而不是由你的包来安装。简而言之，它表示你的库或插件需要依赖某个包，并且你希望宿主应用（使用你这个库的项目）来负责安装这个包，而不是由你的库来安装。

为什么需要 peerDependencies？

1. 避免重复安装：有时候，一个项目中可能会安装多个版本的同一个库，导致版本冲突和冗余。peerDependencies 使得你可以声明库或插件的版本兼容要求，让最终的用户（宿主应用）自己管理这个依赖。
2. 版本兼容性：当你开发一个插件或库时，可能要求宿主应用使用特定版本范围内的依赖。例如，如果你开发的是一个 React 组件库，你可能希望它与宿主应用的 React 版本兼容。通过 peerDependencies，你可以确保宿主应用使用与库兼容的 React 版本。
3. 确保依赖不被覆盖：有时你希望依赖库的版本由主项目来管理，而不是被你的包自动安装（例如，React、Vue 等）。这可以避免不同的版本之间的冲突。

### 使用 peerDependencies

在 package.json 中的 peerDependencies 字段，可以指定所需的依赖项及其版本范围。

示例 1：常见的 peerDependencies 配置

假设你正在开发一个基于 React 的组件库，你希望宿主应用使用 React 16.x 或 17.x 版本，而不是由你来安装 React。

```json
{
  "name": "my-react-component",
  "version": "1.0.0",
  "peerDependencies": {
    "react": "^16.8.0 || ^17.0.0",
    "react-dom": "^16.8.0 || ^17.0.0"
  }
}
```

在这个例子中，my-react-component 声明了对 react 和 react-dom 的 peerDependencies，并且希望宿主项目安装的版本在 16.8.0 到 17.x.x 之间。

示例 2：版本范围

peerDependencies 支持常见的版本范围语法，例如：

- "^16.0.0"：兼容 16.x.x 版本。
- "~16.8.0"：兼容 16.8.x 版本。
- "\*"：任何版本。

peerDependencies 和 dependencies 的区别

- dependencies：表示包的依赖项，当你发布你的包时，dependencies 中列出的包会被自动安装，并且这些依赖项是由你的包来管理的。
- peerDependencies：表示你的包需要某些依赖项，但这些依赖项应该由宿主项目来安装，而不是由你的包来安装。这样可以避免重复安装，并且确保宿主应用安装与依赖包版本兼容的版本。

示例 3：如何在插件中使用 peerDependencies

假设你开发了一个 Vue 插件，要求宿主应用使用 vue 版本 3.x.x：

```json
{
  "name": "vue3-plugin",
  "version": "1.0.0",
  "peerDependencies": {
    "vue": "^3.0.0"
  }
}
```

如果用户在安装这个插件时，未安装兼容的 vue 版本，npm 会发出警告，提醒用户需要安装正确的版本。

peerDependencies 的工作机制

1. 安装时的行为：
   当你安装一个依赖项时，如果该依赖项包含 peerDependencies，npm 会检查这些 peerDependencies 是否满足当前项目中已安装的版本。如果没有安装，npm 会发出警告，提示缺少必需的依赖。
2. 没有自动安装：
   与 dependencies 不同，peerDependencies 并不会自动安装所需的依赖包。你需要手动确保宿主项目安装了兼容的版本。
3. 版本冲突警告：
   如果在宿主项目中安装的版本不符合 peerDependencies 中的版本要求，npm 会发出警告。

示例 4：安装时的警告

假设你有一个包 my-library，它声明了对 react 的 peerDependencies：

```json
{
  "peerDependencies": {
    "react": "^16.8.0 || ^17.0.0"
  }
}
```

然后，在宿主项目中，你安装了 my-library，但并未安装 react，或者安装的 react 版本不兼容。npm 会发出如下警告：

`npm WARN my-library@1.0.0 requires a peer of react@^16.8.0 || ^17.0.0 but none is installed. You must install peer dependencies yourself.`

peerDependencies 与 devDependencies 和 optionalDependencies 的区别

- devDependencies：表示开发过程中使用的依赖，通常用于测试、构建工具、文档生成等。在生产环境中不会安装这些依赖。
- optionalDependencies：表示可选的依赖项，安装时，如果某个可选依赖安装失败，npm 不会阻止安装其他依赖。

总结

- peerDependencies 是用于声明一个包依赖于另一个包，但需要宿主项目来负责安装该依赖项。
- 它通常用于插件、库或组件，确保与宿主应用的依赖版本兼容。
- 它不会自动安装依赖，npm 会根据版本范围检查宿主项目是否安装了合适的依赖，并发出警告。
- peerDependencies 解决了包间依赖版本冲突的问题，尤其是在开发插件或库时，确保与宿主应用的兼容性。
