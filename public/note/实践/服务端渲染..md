# nextjs

**Next.js** 是一个基于 **React** 的 **全栈 Web 应用框架**，由 **Vercel** 团队开发。它在 React 的基础上提供了许多开箱即用的能力，用来解决 React 单页应用（SPA）在 **SEO、性能、路由、部署** 等方面的不足。

---

## 🌍 一句话介绍

> **Next.js = React + 服务端渲染 (SSR) + 文件路由 + 全栈能力 + 优化构建 + 部署无缝对接**

---

## 🧩 主要特性

### 1️⃣ 文件系统路由（File-based Routing）

你不再需要手写 `react-router` 配置，只要在 `app/` 或 `pages/` 目录下创建文件即可：

```bash
app/
 ├─ page.tsx        # 首页
 ├─ about/
 │   └─ page.tsx    # /about 页面
 └─ blog/
     └─ [id]/
         └─ page.tsx  # 动态路由 /blog/123
```

👉 路径结构 = 路由结构。

---

### 2️⃣ 多种渲染模式

Next.js 允许你选择不同的渲染方式，按需优化性能：

| 渲染模式                                  | 描述                   | 使用场景           |
| ----------------------------------------- | ---------------------- | ------------------ |
| **SSR (Server-Side Rendering)**           | 每次请求都在服务端渲染 | 动态数据页面       |
| **SSG (Static Site Generation)**          | 构建时生成静态页面     | 博客、文档类       |
| **ISR (Incremental Static Regeneration)** | 静态页面+按需再生成    | 需要定期更新的数据 |
| **CSR (Client-Side Rendering)**           | 浏览器端渲染           | 用户交互密集场景   |

---

### 3️⃣ App Router（Next.js 13+）

新版 Next.js 使用 `app/` 目录，支持 **React Server Components (RSC)**、**Streaming**、**Layout 共享**：

```tsx
// app/layout.tsx
export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Header />
        {children}
      </body>
    </html>
  );
}
```

所有页面共享该布局，加载速度更快。

---

### 4️⃣ 内置 API 路由

Next.js 不只是前端框架，它还能直接写后端接口：

```tsx
// app/api/hello/route.ts
export async function GET() {
  return Response.json({ message: "Hello from API!" });
}
```

这使得 Next.js 成为一个 **全栈框架**。

---

### 5️⃣ 静态资源优化

内置了多种优化功能：

- ✅ 自动图片优化（`next/image`）
- ✅ 字体优化（`next/font`）
- ✅ 脚本优化（`next/script`）
- ✅ 自动代码分割和懒加载

---

### 6️⃣ TypeScript & ESLint 支持

Next.js 开箱即用 TypeScript，无需手动配置：

```bash
npx create-next-app@latest my-app --typescript
```

---

### 7️⃣ 与 Vercel 深度集成

Next.js 由 Vercel 开发，可以**一键部署**到全球 CDN 节点，支持：

- 无服务器函数（Serverless Functions）
- 边缘渲染（Edge Rendering）
- 自动构建和回滚

## ⚡️ 与传统 React 的区别

| 对比项   | React                    | Next.js                                                           |
| -------- | ------------------------ | ----------------------------------------------------------------- |
| 路由     | 手动配置（react-router） | 文件系统自动生成                                                  |
| 渲染方式 | CSR                      | SSR / SSG / ISR / CSR                                             |
| SEO      | 不友好（客户端渲染）     | 友好（服务端渲染）                                                |

# 服务渲染 & 客户端渲染

非常好的问题 👍
理解 **Next.js 如何处理服务端渲染（SSR）和客户端渲染（CSR）**，是掌握它的核心。我们来系统地讲清楚它的机制和区别。

---

## 🌍 一、背景：React 的渲染模式问题

普通的 **React SPA（单页应用）**：

- 页面首次加载时只有一个空的 `<div id="root"></div>`
- 所有内容都由 JS 在浏览器中执行后生成
- 导致：

  - 首屏白屏时间长
  - SEO（搜索引擎优化）差，因为 HTML 没有真实内容

而 **Next.js** 解决了这个问题 —— 让 React 既能在服务器上渲染（SSR），又能在客户端继续接管交互（Hydration）。

---

## ⚙️ 二、Next.js 的渲染流程总览

Next.js 的渲染可以分为两个阶段：

```
[Server] 生成 HTML 页面 (SSR/SSG)
      ↓
[Client] React Hydration 接管交互 (CSR)
```

也就是说：

- **在服务器上先生成 HTML（带内容）**，返回给浏览器；
- **浏览器再加载 JS 脚本，激活页面交互逻辑**（事件、状态等）。

---

## 🧩 三、三种主要服务端渲染模式

### 1️⃣ SSR（Server-Side Rendering）

**每次请求都在服务器上执行 React 渲染。**

#### 工作原理：

- 请求 `/products/1`
- Next.js 调用组件的 **Server Component**
- 在服务器上执行 `fetch()` 获取数据
- 生成完整 HTML 返回
- 客户端再 “hydrate”

```tsx
// app/products/[id]/page.tsx
export default async function ProductPage({ params }) {
  const product = await fetch(`https://api.example.com/p/${params.id}`).then(
    (r) => r.json()
  );
  return <div>{product.name}</div>;
}
```

📦 **特点：**

- 每次请求都会触发渲染（实时数据）
- 对 SEO 非常友好
- 服务器负载较高

---

### 2️⃣ SSG（Static Site Generation）

**构建时（build 阶段）预生成 HTML 文件。**

#### 工作原理：

- `next build` 阶段调用组件，生成静态 HTML
- 用户访问时，直接返回这个静态页面（性能极高）

```tsx
// app/blog/[slug]/page.tsx
export async function generateStaticParams() {
  const posts = await fetch("https://api.example.com/posts").then((r) =>
    r.json()
  );
  return posts.map((p) => ({ slug: p.slug }));
}
```

📦 **特点：**

- 页面构建后就不会变（除非重新构建）
- 响应速度极快（CDN 缓存）
- 不适合频繁变动的数据

---

### 3️⃣ ISR（Incremental Static Regeneration）

**在静态生成的基础上，支持定期再生。**

#### 工作原理：

- 初次访问时返回旧的静态页面
- 后台异步重新生成最新版本（缓存刷新）

```tsx
export const revalidate = 60; // 每 60 秒后台再生成一次
```

📦 **特点：**

- 性能接近静态化
- 数据可定期更新
- 非常适合新闻、商品展示类站点

---

## 💻 四、客户端渲染（CSR）

即传统的 React 渲染：由浏览器执行组件逻辑、请求数据、更新 UI。

在 Next.js 中：

- 任何带 `"use client"` 的组件都是 **Client Component**
- 它在浏览器执行，支持 hooks（`useState`, `useEffect` 等）

```tsx
"use client";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>点击 {count}</button>;
}
```

📦 **特点：**

- 不会在服务器渲染
- 不适合放耗时逻辑或数据请求
- 用于页面交互、事件响应

---

## ⚖️ 五、SSR 与 CSR 如何协作（混合渲染）

Next.js **在一个页面中可以同时存在服务端组件和客户端组件**：

```tsx
// app/page.tsx
import Counter from "./Counter"; // Client component

export default async function Page() {
  const data = await fetch("https://api.example.com/info").then((r) =>
    r.json()
  );
  return (
    <div>
      <h1>{data.title}</h1> {/* SSR 渲染 */}
      <Counter /> {/* CSR 渲染 */}
    </div>
  );
}
```

🧠 渲染过程：

1. 服务器执行 Page → 输出带有 `<h1>` 的 HTML
2. Counter 部分由客户端 JS 执行（hydrate）

这种混合渲染模式让页面 **既有 SEO 优势，又能交互流畅**。

---

## 🚀 六、总结对比表

| 渲染模式 | 渲染位置    | 生成时机   | 数据新鲜度  | 性能    | SEO     | 典型场景       |
| -------- | ----------- | ---------- | ----------- | ------- | ------- | -------------- |
| **SSR**  | 服务器      | 每次请求时 | ✅ 最新     | ⚠️ 中等 | ✅ 优秀 | 动态内容       |
| **SSG**  | 构建时      | 构建阶段   | ❌ 固定     | 🚀 极快 | ✅ 优秀 | 博客、文档     |
| **ISR**  | 服务器+缓存 | 首次访问后 | ✅ 定期更新 | 🚀 快   | ✅ 优秀 | 新闻、商品列表 |
| **CSR**  | 客户端      | 加载后     | ✅ 最新     | ⚠️ 慢   | ❌ 差   | 仪表盘、表单类 |
